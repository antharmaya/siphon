# siphon roadmap — competitor research + feature plan (2026-10-10)

Personal tool. Goal: make siphon a complete, standalone, fast downloader that needs no other
app. This is the research the features are chosen from, not a marketing doc.

## What the competitors are, and what people actually use

| Tool | Shape | The feature people love it for |
|---|---|---|
| **IDM** | Windows app + browser hook | **Speed** (dynamic segmentation, "5×"), **resume**, **scheduler**, one-click grab |
| **JDownloader 2** | Java desktop | **Link grabber** (clipboard watch, deep-decrypt), **queue**, batch, archive extraction, bandwidth cap |
| **yt-dlp** | CLI | 1,700+ site extractors (1,750 counted 2026-10-11, 1,614 marked working), **format selection**, **SponsorBlock**, **--download-sections** (clips), embed metadata/subs/chapters, **--download-archive**, playlists |
| **4K Video Downloader** | GUI | **Smart Mode** (remember format/quality), playlists & channels, subtitles, up to 8K |
| **cobalt.tools** | web | **minimal, fast, no ads/trackers, privacy** — "paste link, get file, move on" |
| **Video DownloadHelper** | extension | sniff any page, **capture-while-playing** (blob/MSE), button on the page |
| **gallery-dl** | CLI | image posts (Twitter/IG/Reddit/Pixiv), full-res, metadata |
| **streamlink** | CLI | live streams, **--retry-streams** (wait for a broadcast) |

**The patterns people consume most, across all of them:** speed + resume (table stakes), a
button in the browser, format/quality choice, SponsorBlock, clip/section trim, playlists/batch,
embed metadata/subs, queue + scheduler, and — cobalt's whole thesis — being fast, clean, and
private with zero friction.

## Gaps, ranked by how much they complete the product

**P0 — shipped this session:** SponsorBlock, clip/section, rate limit, download-archive.

**P1 — next, high value, low cost**
1. ~~**Download queue + concurrency cap**~~ ✓ shipped 2026-10-10 (`siphon queue add/list/run/clear`).
   Extension "add to queue" UI still to do.
2. **Scheduler** (`--at`, or cron-style) — "download at 2am". Cheap once a queue exists.
3. **Clipboard watch / link grabber** (extension already has the hook; add a watch-mode).
4. **Playlist/channel UI in the extension** (CLI already does playlists via yt-dlp).
5. **Rate limit for the segmented downloader too** (currently yt-dlp path only).

**P2 — breadth**
6. **Instagram at scale, cloud drives** (Drive/Dropbox/MEGA) — gallery-dl + dedicated handlers.
7. **Wait-for-live** (`--wait`) — streamlink's retry-streams, via yt-dlp `wait_for_video`.
8. **Settings/profile** — remember default preset/format/output dir (4K VD's "Smart Mode").
9. **Thumbnail + quality picker in the extension popup** before download.
10. **SponsorBlock / section controls surfaced in the extension UI** (CLI has them now).

**P3 — the "my own product" polish**
11. A small **local web dashboard** (reuse the existing CDP/httpx stack) — history, queue, re-download.
12. **Subtitle-only / chapters-only** download modes.
13. **Format conversion** opt-in (re-encode to a target codec) — against the "never re-encode"
    default, so strictly opt-in.
14. **Self-update + a one-line installer** for the CLI (the launch-from-GitHub path).

## Design rules carried forward

- **Never re-encode by default.** Choose among served streams; conversion is opt-in only.
- **Instant where the browser already has access** (images/files via chrome.downloads); the host
  and headless sniff are for streams and extractor sites only.
- **Fast, clean, private** (cobalt's bar): no telemetry, no accounts, minimal dependencies
  (Playwright already dropped; curl_cffi optional).
- **Verify against reality**: every feature checked on a real download, not just a passing config.
